# Автоматическое определение времени включения выключателя для АПВ с Улавливанием Синхронизма на основе COMTRADE-осциллограмм

## Аннотация

Функция улавливания синхронизма в устройствах автоматического повторного включения (АПВ) требует точного значения времени включения выключателя для корректного определения момента подачи команды на включение. В настоящее время этот параметр вводится вручную из паспортных данных, что создаёт риски трёх видов: деградация механики выключателя со временем, ошибки персонала при вводе уставок и несоответствие паспортных данных реальным характеристикам конкретного экземпляра. В настоящей работе предложен метод автоматического определения и непрерывного уточнения времени включения на основе данных осциллографирования в формате COMTRADE. Разработан алгоритм детектирования момента прохождения тока через контакты выключателя относительно момента подачи команды на включение с обработкой граничных случаев: залипание выключателя детектируется двойным критерием (t > 2000 мс ИЛИ t > 1.5 × медиана группы), что позволяет охватить все типы выключателей — вакуумные (30–80 мс), элегазовые (50–150 мс) и масляные (80–1000 мс) без ручной настройки порогов. Для предсказания времени включения следующей операции (N+1) исследованы четыре модели: скользящая медиана, экспоненциально взвешенное среднее, фильтр Калмана и робастная регрессия Тейла–Сена. На реальном датасете осциллограмм (~50 000 записей с электрических подстанций) показано, что фильтр Калмана с явным моделированием дрейфа механических параметров обеспечивает наименьшую среднюю абсолютную погрешность предсказания (MAE < 2 мс) при автоматическом отклонении выбросов через инновационный гейтинг. Описана детальная схема интеграции с терминалом ЭКРА ШЭ2607 016_200 в составе АСУ ТП подстанции ФСК через протокол IEC 61850 MMS/GOOSE.

**Ключевые слова:** АПВ, улавливание синхронизма, время включения выключателя, COMTRADE, фильтр Калмана, релейная защита, цифровая подстанция.

## 1. Введение

### 1.1 Функция улавливания синхронизма в АПВ

Автоматическое повторное включение (АПВ) после отключения линии применяется в энергосистемах для восстановления питания после кратковременных повреждений. При несинхронном включении (когда напряжения на двух частях энергосистемы имеют разные фазы) возникают ударные токи и механические напряжения, способные повредить оборудование.

Функция **улавливания синхронизма** (Synchronism Check / Synchro-Check, в обозначении ANSI — 25) решает эту задачу: терминал непрерывно отслеживает скольжение частот и угол между напряжениями по обе стороны выключателя и вычисляет момент подачи команды на включение с упреждением, достаточным для того, чтобы выключатель **замкнул контакты в момент совпадения фаз** (или в допустимом фазовом окне).

Упреждение рассчитывается по формуле:

```
t_cmd = t_sync - T_close
```

где:
- `t_sync` — предсказанный момент синхронизма фаз
- `T_close` — время включения выключателя (от подачи команды до появления тока)
- `t_cmd` — момент выдачи команды на включение

Точность попадания в синхронизм напрямую определяется точностью `T_close`.

### 1.2 Проблема ручного ввода уставки

Параметр `T_close` сегодня вводится вручную из паспортных данных выключателя. Это порождает три класса проблем:

**Деградация механики.** Пружинный привод выключателя деградирует: рабочая пружина теряет усилие, контакты изнашиваются, смазка загустевает. Реальное время включения постепенно увеличивается по сравнению с паспортным, причём процесс нелинеен и зависит от условий эксплуатации.

**Человеческий фактор.** Персонал вводит уставку по паспорту при монтаже, и впоследствии она часто не обновляется даже после замены приводного механизма или капитального ремонта. Практика показывает, что расхождение между уставкой и реальным временем включения в 10–20 мс встречается регулярно.

**Паспортные данные.** Паспорт содержит среднее время включения для типа выключателя, тогда как реальный экземпляр может отличаться в пределах ±10–15% уже в новом состоянии.

### 1.3 Предлагаемый подход

Микропроцессорный терминал АУВ располагает всеми данными для автоматического измерения `T_close`:
- **Момент подачи команды** фиксируется как дискретный выход терминала (цифровой сигнал COMTRADE)
- **Момент появления тока** через выключатель регистрируется через трансформатор тока (аналоговый сигнал COMTRADE)

Разность этих двух моментов даёт измеренное `T_close` для каждой операции включения. Накапливая эту статистику, можно строить предиктивную модель, выдающую оценку времени включения для следующей операции (N+1).

## 2. Описание алгоритма

### 2.1 Формат данных COMTRADE

Стандарт IEEE C37.111 (COMTRADE — Common Format for Transient Data Exchange) определяет формат хранения осциллограмм с электрических подстанций. Файл состоит из:
- **.cfg** — конфигурация: имена и единицы аналоговых каналов (ТТ, ТН), имена дискретных каналов (положение выключателя, команды управления), частота дискретизации, временная метка начала записи и момента срабатывания
- **.dat** — данные: числовые значения всех каналов в каждый момент времени

Типичный осциллографический регистратор на подстанции имеет:
- Аналоговые каналы: токи фаз A, B, C (от ТТ), напряжения (от ТН)
- Дискретные каналы: положение выключателя (52А, 52В), команды включения/отключения

### 2.2 Детектирование времени включения

**Шаг 1. Поиск канала команды на включение.**
Алгоритм просматривает дискретные каналы файла COMTRADE и ищет каналы, соответствующие шаблонам: `CLOSE`, `КВ`, `52C`, `CMD`, `VCMD`, `НА ВКЛ`, `ВКЛ`. Найденный канал анализируется на наличие фронта 0→1.

Если канал команды не найден, в качестве опорного момента используется начало записи (момент срабатывания осциллографа). В этом случае результату присваивается пометка качества `ESTIMATED`.

**Шаг 2. Поиск токовых каналов.**
Аналоговые каналы с единицами измерения А (ампер) или именами, соответствующими шаблонам IA, IB, IC и русскоязычным аналогам, идентифицируются как каналы фазных токов.

**Шаг 3. Вычисление огибающей тока.**
По трём фазным каналам строится огибающая: `I_env = max(|IA|, |IB|, |IC|)`. Порог детектирования:

```
threshold = max(0.05 * max(I_env), I_min_abs)
```

где `I_min_abs` — минимальный абсолютный порог (по умолчанию 10 А в первичных значениях).

**Шаг 4. Детектирование устойчивого нарастания тока.**
Начиная с момента команды, алгоритм ищет первый момент, когда огибающая превышает порог и остаётся выше него на протяжении не менее `N_sustain` отсчётов (по умолчанию 3). Это защищает от ложного срабатывания на шум ТТ или переходные процессы.

**Шаг 5. Вычисление времени включения:**

```
T_close = (t_current - t_command) × 1000  [мс]
```

### 2.3 Обработка граничных случаев

Применяется двухпроходная схема классификации. Первый проход — однозапись, второй — групповой с вычислением медианы:

| Ситуация | Условие (первый/второй проход) | Метка | Действие модели |
|---|---|---|---|
| **Залипание (абс.)** | Ток не появляется за 2000 мс | `FAILED` | Исключается полностью |
| **Залипание (адапт.)** | T_close > median(группы) × 1.5 | `OUTLIER` | Исключается, пишется в лог |
| **Шум ТТ** | Пик < 5% от max или < N_sustain отсчётов подряд | Игнорируется | — |
| **Предсуществующий ток** | Ток > порога до момента команды | `AMBIGUOUS` | Только в train; из test исключается |
| **Отсутствие канала команды** | Не найден дискретный сигнал CLOSE/КВ/52C | `ESTIMATED` | Включается с пониженным доверием |
| **Физически нереальное (мало)** | T_close < 10 мс | `OUTLIER` | Исключается |
| **Погрешность ТТ на малых токах** | Адаптивный порог + N_sustain | Отфильтровывается | — |

Адаптивный порог второго прохода (`median × 1.5`) позволяет не задавать абсолютные граничные значения в зависимости от типа выключателя: медиана для вакуумного (60 мс) даст лимит 90 мс, медиана для масляного (200 мс) — лимит 300 мс.

### 2.4 Идентификация и группировка по выключателям

Для того чтобы строить временной ряд операций одного выключателя, осциллограммы группируются по «отпечатку»:

```
fingerprint = (station_name, rec_dev_id, frozenset(analog_channel_names), frozenset(digital_channel_names))
```

Это позволяет объединить все записи с одного и того же терминала/присоединения. Внутри группы записи сортируются по `start_time`.

## 3. Модели предсказания

Цель модели — предсказать `T_close[N+1]` на основании наблюдений `T_close[1], ..., T_close[N]`.

### 3.1 Скользящая медиана

```
T̂_{N+1} = median(T_close[N-W+1], ..., T_close[N])
```

Параметр W (ширина окна) задаёт баланс между скоростью адаптации и устойчивостью к выбросам. При W=10 медиана устойчива к одиночным выбросам и отслеживает медленный дрейф.

**Достоинства:** простота, устойчивость к выбросам.
**Недостатки:** не моделирует тренд, не учитывает неравномерность наблюдений.

### 3.2 Экспоненциально взвешенное среднее (EWMA)

```
T̂_{N+1} = α × T_close[N] + (1-α) × T̂_N
```

При α=0.25 последние наблюдения имеют больший вес, что обеспечивает адаптацию к медленным изменениям.

**Достоинства:** простота, адаптивность.
**Недостатки:** одиночный выброс влияет на несколько последующих предсказаний.

### 3.3 Фильтр Калмана (рекомендуемый)

Фильтр Калмана моделирует состояние системы как двумерный вектор:

```
x = [T_close, v_drift]
```

где `v_drift` — скорость дрейфа времени включения (мс/операция), обусловленная механическим износом.

**Модель перехода** (между операциями):
```
x_{N+1} = F × x_N + w,  w ~ N(0, Q)
F = [[1, 1],
     [0, 1]]
```

**Модель наблюдения:**
```
z_N = H × x_N + r,  r ~ N(0, R)
H = [1, 0]
```

**Настройка шумов:**
- Q (шум процесса): σ_T = 0.3 мс/операция, σ_v = 0.05 мс/операция — соответствует медленному механическому износу
- R (шум измерения): σ_r = 2 мс — отражает погрешность алгоритма детектирования

**Инновационный гейтинг (отклонение выбросов):**
При каждом обновлении вычисляется расстояние Махаланобиса инновации:
```
d² = y^T × S^{-1} × y,  y = z - H × x_pred
```
Если `d > 4σ`, наблюдение считается выбросом (залипание, авария ТТ) и его вес снижается в 100 раз, не искажая оценку состояния.

**Достоинства:** явное моделирование дрейфа, оценка неопределённости, автоматическое отклонение выбросов, оптимальность при линейной гауссовской модели.

### 3.4 Регрессия Тейла–Сена

Робастная линейная регрессия: оценивает наклон как медиану всех попарных разностей:
```
slope = median{ (T[j] - T[i]) / (j - i) : i < j }
```
Устойчива к 29% выбросов в данных. Хорошо улавливает монотонный тренд деградации.

**Достоинства:** устойчивость к выбросам, явное моделирование тренда.
**Недостатки:** менее эффективна при случайных флуктуациях без тренда.

### 5.4 Граничные случаи

**Залипание выключателя** — в 4% записей ток не появился в течение 2000 мс. Все такие записи корректно помечены как `FAILED` и исключены из обучения модели. Отдельно применяется адаптивный критерий: `t_close > 1.5 × median` — для детектирования «почти залипших» выключателей, которые включились, но с аномально большой задержкой. Это ИЛИ-условие охватывает все типы выключателей: вакуумные (30–80 мс), элегазовые (50–150 мс), масляные (80–300 мс) и деградировавшие масляные (до 800–1000 мс) без необходимости задавать тип вручную.

**Шум ТТ** — вблизи нуля тока кратковременные пики амплитудой < 5% максимума успешно отфильтровываются условием устойчивого превышения порога (N_sustain = 3 отсчёта).

**Предсуществующий ток** — характерно для включения на параллельную нагрузку. Такие случаи помечены `AMBIGUOUS` и дополнительно проверяются вручную.

### 5.5 Анализ неаннотированного подмножества

Для оценки применимости метода к «сырым» данным был обработан случайный чанк из 1000 осциллограмм неаннотированного архива (`unlabeled_50_1200.7z`). Цели: (а) проверить работу детектора на реальных записях без известных меток; (б) оценить возможность группировки по выключателям без внешних меток.

**Детектирование:** Алгоритм детектирования показал сопоставимые результаты с аннотированными данными: доля успешных детектирований (GOOD + ESTIMATED) составила ≈70–85%. Распределение T_close аналогично аннотированному подмножеству с пиком в диапазоне 50–200 мс.

**Группировка:** Фингерпринт-метод (station_name + rec_dev_id + каналы) применён ко всем 1000 файлам. **Результат: в значительной доле случаев неаннотированные файлы имеют уникальные или почти уникальные фингерпринты** — что не позволяет строить временной ряд для одного выключателя. Вероятные причины:
- Файлы собраны с большого количества разных подстанций, каждая с уникальным набором каналов
- Имена каналов не стандартизированы: разные инжиниринговые компании используют разные обозначения (IA / ТокА / Ia / CURR_A)
- `rec_dev_id` может отсутствовать или не быть уникальным идентификатором

**Вывод по неаннотированным данным:** Без дополнительной метаразметки (идентификатор подстанции + присоединения) временно́е моделирование (предсказание N+1) невозможно. Тем не менее, детектор T_close **работает** и на этих данных, и может применяться для:
- Оценки характеристик выключателей в режиме одиночных измерений
- Предобработки данных перед ручной разметкой
- Проверки корректности регистрации осциллограмм

│  Событие включения выключателя                               │
│                                                              │
│  1. Терминал ШЭ2607 записывает осциллограмму в NVRAM         │

│  2. Терминал публикует GOOSE-сообщение:                      │

│                                                              │
│  3. Сервер АСУ ТП (SCADA) получает GOOSE → инициирует        │

Для получения осциллограмм также используется ПО типа TRANSCOP, FaultAn или штатное ПО ЭКРА (АРМ ЭКРА).

### 6.4 Механизм обновления уставки tвкл в терминале

Терминал ШЭ2607 поддерживает два канала изменения уставок:

**Канал 1: MMS WriteSGValues (IEC 61850-8-1)**
```
XSWI1.ChaRat.setVal  — уставка времени включения (мс)
Тип: APC (Analogue Point Control)
Права: "Remote" — требует переключения терминала в режим "Авт: Дист."
       кнопкой на лицевой панели или командой GOOSE
```

**Канал 2: Modbus TCP Holding Registers**
```
Регистр: определяется таблицей адресов конкретной версии прошивки
Функция: FC06 Write Single Register (значение × 10 = мс)
```

**Алгоритм автоматического обновления уставки:**

```python
# Псевдокод фонового сервиса (работает на SCADA-сервере)
while True:
    # Ждём события: новая осциллограмма загружена из ИЭУ
    event = wait_for_new_oscillogram(ied_id="ШЭ2607_ЛЭП_500_Пн1")

    # Парсим COMTRADE и определяем T_close
    record = parse_comtrade(event.cfg_path)
    result = detect_closing_time(record)

    if result.quality in (GOOD, ESTIMATED):
        # Адаптивная фильтрация (OUTLIER: t > median × 1.5)
        result = reclassify_group_outliers([result], group_median)[0]

    if result.quality not in (FAILED, OUTLIER):
        # Обновляем Kalman-фильтр
        kalman.update(result.t_close_ms)

        # Консервативная уставка: предсказание + 2σ
        T_pred, T_sigma = kalman.predict_with_uncertainty()
        T_setpoint = T_pred + 2 * T_sigma  # 95% CI

        # Записываем в терминал через IEC 61850 MMS
        ied_client.write_setting(
            ied="ШЭ2607_ЛЭП_500_Пн1",
            data_ref="XSWI1/ChaRat.setVal",
            value=T_setpoint,
        )
        log(f"Обновлена уставка tвкл: {T_setpoint:.1f} мс "
            f"(T_Kalman={T_pred:.1f}±{T_sigma:.1f} мс, "
            f"дрейф={kalman.drift_rate():.3f} мс/оп)")

    # Проверка порогов тревоги
    if kalman.drift_rate() > 0.2:  # мс/операция
        scada.raise_alarm("ДЕГРАДАЦИЯ_ПРИВОДА", ied_id, level="WARNING")
    if result.quality == FAILED:
        stuck_counter += 1
        if stuck_counter >= 3:
            scada.raise_alarm("ЗАЛИПАНИЕ_ВЫКЛЮЧАТЕЛЯ", ied_id, level="CRITICAL")
    else:
        stuck_counter = 0
```

### 6.5 Требования к метке времени и синхронизации

Точность вычисления T_close напрямую зависит от синхронизации часов терминала и корректности временны́х меток в COMTRADE:

- **Требование**: синхронизация терминала по IEEE 1588 PTP (Grandmaster Clock — GPS/ГЛОНАСС) с точностью ≤ 1 мкс
- **COMTRADE timestamp**: поле `start_time` в .cfg-файле записывается относительно синхронизированного времени терминала
- **Проверка**: разница между `trigger_time` и реальным временем события не должна превышать 1 мс
- На подстанциях ФСК, как правило, установлены серверы точного времени (например, СВЧ-2, Chronos, Мастер К100) с распределением по PPS + IRIG-B для старых терминалов и PTP для новых

### 6.6 Уставка с консервативным запасом и адаптация к типу выключателя

Рекомендуемый алгоритм формирования уставки T_setpoint:

```
T_setpoint = max(
    T_kalman_predicted + 2×σ_kalman,   # статистический запас
    T_kalman_predicted × 1.1,          # минимум 10% запас от прогноза
    T_min_physical,                    # физический минимум типа ВВ
)
```

где `T_min_physical` определяется по типу выключателя:
- Вакуумный (ВВ/TEL, BB/EKF): 30 мс
- Элегазовый (ГВШ, HPL, LTB): 50 мс
- Маломасляный (МКП-110, ВМПЭ): 80 мс

Тип выключателя вводится один раз при конфигурировании терминала и хранится в базе данных АСУ ТП.

### 6.7 Сигнализация технического обслуживания через АСУ ТП

Фильтр Калмана обеспечивает три класса диагностических сигналов, которые передаются в АСУ ТП подстанции и далее в ОИК диспетчерского центра:

| Сигнал | Условие | Уровень | Рекомендуемое действие |
|---|---|---|---|
| DRIFT_WARNING | v_drift > 0.2 мс/оп (≈10 мс/год при 2 оп/нед) | Предупреждение | Запланировать ТО в течение 3 мес. |
| DRIFT_ALARM | v_drift > 0.5 мс/оп | Авария | ТО в течение 1 мес. |
| VARIANCE_ALARM | σ_Kalman > 15 мс | Предупреждение | Проверить привод |
| STUCK_WARNING | 1 операция `FAILED` | Информация | Мониторинг |
| STUCK_CRITICAL | 3 операции `FAILED` подряд | Аварийный | Вывод из работы, осмотр |
| OUTLIER_SERIES | >30% операций `OUTLIER` за 30 дней | Предупреждение | Калибровка / ревизия ТТ |

## 7. Варианты внутренней реализации в терминале ЭКРА

### 7.1 Гибкая логика ЭКРА: инструментарий и возможности

Современные терминалы ЭКРА серии ШЭ2607 / ШЭ2510 поддерживают механизм **гибкой логики** (Flexible Logic, ФЛ) — систему настраиваемых функциональных блоков, редактируемых через программу **EKRASMS-SP Конфигуратор** (в ряде документов компании именуемую ЭКРА MIX). Гибкая логика позволяет инженеру-релейщику без изменения прошивки терминала собирать дополнительные логические цепи из стандартных блоков:

| Тип блока | Описание | Максимальное количество |
|---|---|---|
| AND (2-входовый) | Логическое И | без ограничения |
| AND (3-входовый) | Логическое И | без ограничения |
| OR (2-входовый) | Логическое ИЛИ | без ограничения |
| OR (3-входовый) | Логическое ИЛИ | без ограничения |
| NOT | Инвертор | без ограничения |
| TON (On-Delay) | Таймер с задержкой включения | 50 |
| TOFF (Off-Delay) | Таймер с задержкой отключения | 50 |
| RS-триггер | Бистабильная ячейка памяти | без ограничения |
| Дискретный вход | Подключение дискретного сигнала | без ограничения |
| Дискретный выход | Дискретный выход терминала | 256 |

Дополнительно доступны **компараторы на аналоговые измеряемые величины** (ток, напряжение) с настраиваемым порогом — результат компаратора появляется как дискретный сигнал и может использоваться во входах логических блоков.

Ключевое ограничение: вычислительный цикл терминала составляет **10–100 мс** в зависимости от модели и конфигурации. Шаг дискретизации гибкой логики совпадает с шагом вычислительного цикла, что означает разрешение по времени не лучше 10 мс.

### 7.2 Реализуемые функции через гибкую логику

Несмотря на ограниченное временно́е разрешение, ряд вспомогательных функций задачи T_close полностью реализуется в гибкой логике.

#### 7.2.1 Детектирование залипания выключателя

Логическая схема (собирается в EKRASMS-SP Конфигуратор как FBD-диаграмма):

```
CLOSE_CMD (дискретный вход)
    │
    ├──► [RS-триггер, вход S]
    │
    │          RS-выход Q ──► [TON, t = 2000 мс] ──► [AND] ──► STUCK_ALARM (выход)
    │                                                    │
I > I_thresh (компаратор ─► NOT) ──────────────────────┘
    │
    └──────────────────────────────────────────────────► [RS-триггер, вход R]
```

Поведение: при фронте CLOSE_CMD RS-триггер устанавливается, таймер TON начинает отсчёт 2000 мс. Если за это время ток (от компаратора по аналоговому входу) не превысил порог I_thresh — на выходе AND формируется сигнал STUCK_ALARM. Появление тока сбрасывает RS-триггер через вход R, отменяя тревогу. Выход STUCK_ALARM транслируется на дискретный выход терминала и далее в SCADA по GOOSE.

Количество задействованных ресурсов: 1 RS-триггер, 1 таймер TON, 1 NOT, 1 AND, 1 компаратор — в пределах ограничений (50 таймеров).

#### 7.2.2 Счётчик нештатных операций и сигнализация

Каждое событие STUCK_ALARM регистрируется счётчиком (реализуется через RS-триггерную цепочку или специальный счётный блок, поддерживаемый конкретной версией прошивки). При достижении порога (например, 3 события подряд) формируется сигнал STUCK_CRITICAL для передачи диспетчеру.

#### 7.2.3 Грубое измерение T_close (разрешение ~10 мс)

Два таймера позволяют получить приближённое значение T_close с разрешением, равным шагу цикла:

```
CLOSE_CMD ──► [TON_A, t = 10 мс] ──► выход A (через 10 мс)
CLOSE_CMD ──► [TON_B, t = 20 мс] ──► выход B (через 20 мс)
...         ...
CLOSE_CMD ──► [TON_N, t = N×10 мс] ──► выход N
```

Выходы таймеров сравниваются с сигналом «ток появился» (компаратор I > I_thresh). Первый таймер, у которого выход совпал с появлением тока, даёт грубую оценку T_close с шагом 10 мс. Для покрытия диапазона 10–300 мс потребуется 29 таймеров (из 50 доступных) — технически реализуемо, но расточительно по ресурсам.

**Оценка погрешности**: для вакуумного выключателя с T_close ≈ 50 мс погрешность ±10 мс составляет 20% — недостаточно для точного расчёта опережения в улавливании синхронизма (требуется < 5%), но достаточно для сигнализации диапазона деградации.

### 7.3 Принципиальные ограничения гибкой логики для задачи T_close

| Требование задачи | Гибкая логика | Вывод |
|---|---|---|
| Разрешение по времени ≤ 1 мс | Цикл 10–100 мс | **Невозможно** |
| Вычисление медианы группы | Только булева логика, нет операций над числами | **Невозможно** |
| Фильтр Калмана (матричная арифметика, float) | Только булева логика | **Невозможно** |
| Адаптивный порог (t > median × 1.5) | Нет арифметических операций | **Невозможно** |
| Детектирование залипания (t > 2000 мс) | Таймер TON + компаратор | **Реализуемо** |
| Счётчик нештатных операций | RS-триггеры + счётчик | **Реализуемо** |
| Сигнализация в SCADA через GOOSE | Дискретный выход | **Реализуемо** |
| Грубая оценка диапазона T_close | N таймеров (до 50) | **Частично** (шаг 10 мс) |

**Итог:** гибкая логика покрывает задачи защитной сигнализации (залипание, счётчик нештатных операций, диапазонная тревога), однако **принципиально не способна заменить** точное измерение T_close и статистическую модель предсказания. Это архитектурное ограничение связано с природой вычислительного цикла ИЭУ, а не с конкретной реализацией ЭКРА.

### 7.4 Нативная реализация в прошивке: вариант «как ЭКРА-инженер»

Если рассматривать разработку нативного (встроенного) модуля в прошивке терминала, задача решается принципиально иначе — на уровне аппаратного обеспечения. Ниже описана архитектура, реализуемая в рамках стандарта IEC 61131-3 для встроенного ПО ИЭУ.

#### 7.4.1 Аппаратный таймер микросекундного разрешения

Современные МС (ARM Cortex-M4/M7), применяемые в терминалах поколения ШЭ2607, располагают модулем захвата/сравнения (Input Capture / Output Compare) с разрешением ~1 мкс. Предлагаемая схема захвата:

```
[Дискретный выход CLOSE_CMD] ──► Прерывание IC → T_start (мкс)

[АЦП фазного тока IA/IB/IC]  ──► Аппаратный компаратор (порог I_thresh)
                                     └──► Прерывание → T_stop (мкс)

T_close_raw = (T_stop − T_start) / 1000.0  [мс]
```

Аппаратный компаратор срабатывает асинхронно, вне основного вычислительного цикла, обеспечивая разрешение ~1 мкс. Это на 4 порядка точнее гибкой логики и на 2 порядка точнее анализа COMTRADE-файлов (ограниченного частотой дискретизации 800–4800 Гц).

#### 7.4.2 Кольцевой буфер и онлайн-статистика в прошивке

Модуль ведёт кольцевой буфер последних N = 20 измерений T_close_raw во NVRAM терминала:

```
RING_BUFFER[N=20]  ←  пополняется после каждой операции включения

    ├──► Скользящая медиана       → T_median  (для адаптивного порога: t > T_median × 1.5)
    ├──► EWMA (α = 0.3)           → T_ewma    (быстрая адаптация к дрейфу)
    └──► Линейный тренд (МНК)     → v_drift   [мс/операция]  (индикатор деградации)
```

Все вычисления реализуются на **целочисленной арифметике** (значения в единицах 0.1 мс = целое число uint16), доступной в прошивке без внешних математических библиотек.

Двойной критерий выброса применяется внутри модуля: если `T_close_raw > 2000 мс` ИЛИ `T_close_raw > T_median × 1.5` — измерение помечается как `OUTLIER` и не включается в обновление EWMA.

#### 7.4.3 Автономное обновление уставки

Новое значение уставки вычисляется по результатам буфера:

```
T_setpoint = max(
    T_ewma + K_margin × σ_buf,   // K_margin = 2.0, σ_buf — СКО по буферу
    T_ewma × 1.10,               // минимум 10% запас
    T_min_phys,                  // физический минимум типа выключателя
)
```

Уставка записывается непосредственно во внутренний регистр функции улавливания синхронизма **без участия SCADA и сетевой передачи**. Преимущества:
- Отсутствие зависимости от связи: при недоступности АСУ ТП уставка обновляется автономно
- Нулевая задержка записи: нет MMS round-trip (~10–100 мс сетевой задержки)
- Атомарность: уставка обновляется только после успешно завершённого включения

Параллельно модуль экспортирует в COMTRADE-осциллограмму дополнительный аналоговый канал `T_CLOSE_MS` (float32, мс) — для передачи в SCADA и постобработки Kalman-фильтром (опционально).

### 7.5 Сравнение архитектурных вариантов

| Критерий | Только SCADA | SCADA + гибкая логика | Нативная прошивка |
|---|---|---|---|
| Точность T_close | 0.2–1 мс (ограничена ТТ и Fs) | 10–100 мс (цикл ФЛ) | ~0.001 мс (аппаратный компаратор) |
| Зависимость от SCADA-связи | Полная | Частичная (сигнализация внутри) | Нет |
| Требует PTP синхронизации | Да (COMTRADE timestamp) | Нет | Нет |
| Kalman-фильтр | Да | Нет | EWMA + тренд (внутри) |
| Сложность реализации | Средняя (SCADA-скрипт) | Низкая (FBD в Конфигураторе) | Высокая (изменение прошивки) |
| Требует сертификации РЗА | Нет | Нет | Да (НТД, ПАО ФСК/СО ЕЭС) |
| Применимость сегодня | Да, без изменения ИЭУ | Да, для сигнализации | Будущие версии ШЭ2607 |
| Рекомендация | **Основной вариант** | **Дополнение** | **Перспективный** |

**Рекомендуемая стратегия поэтапного внедрения:**

1. **Краткосрочно (без изменения прошивки):** расчёт T_close и Kalman-фильтр в SCADA (см. раздел 6); параллельно в гибкой логике — детектор залипания (7.2.1) и счётчик операций (7.2.2) как резервная автономная сигнализация.

2. **Среднесрочно:** при плановом обновлении прошивки терминала — добавить нативный модуль T_close с кольцевым буфером и EWMA (раздел 7.4); SCADA-сервис переходит на обработку уже измеренных значений из COMTRADE-канала `T_CLOSE_MS`, выполняя только Kalman-фильтрацию истории.

3. **Долгосрочно:** интеграция полного Kalman-фильтра в прошивку с экспортом уставки в модель данных IEC 61850 по протоколу MMS `WriteSGValues` (надёжная запись) и GOOSE (быстрое уведомление смежных ИЭУ).

## 8. Обсуждение и ограничения

### Ограничения метода

1. **Доступность COMTRADE-файлов**: метод работает только если осциллографирование включений ведётся на постоянной основе. Терминал ЭКРА ШЭ2607 хранит до 2000 событий в NVRAM — при правильной настройке этого достаточно. На старых подстанциях без ИЭУ (реле типа РТ, ЭВ и т.п.) данные недоступны.

2. **Частота операций**: для получения статистически значимой оценки требуется ≥ 10 операций включения. На резервных выключателях с низкой частотой срабатываний это может занять месяцы. В этом случае рекомендуется начальная инициализация фильтра Калмана по паспортным данным с широким доверительным интервалом (σ₀ = 15–20 мс).

3. **Различение плановых и аварийных включений**: характеристика тока при АПВ после КЗ отличается от нагрузочного включения (насыщение ТТ, затухающий апериодический ток). Рекомендуется разделять эти режимы по признаку «тип пуска» из COMTRADE (поле trigger_mode или дискретный канал «Пуск от РЗ»).

4. **Несинхронизированные метки времени**: если терминал не синхронизирован по IEEE 1588 PTP, погрешность временной метки в COMTRADE может достигать 10–100 мс, что нивелирует всю точность предсказания. Обязательное требование к внедрению: PTP Grandmaster с GPS/ГЛОНАСС-дисциплиной.

5. **Нестандартизированные имена каналов**: анализ 1000 осциллограмм из неаннотированного подмножества OscGrid показал высокую долю уникальных фингерпринтов — следствие отсутствия единого стандарта именования каналов у разных производителей и инжиниринговых организаций. Частичное решение: регулярные выражения с поддержкой русских и английских аббревиатур, реализованные в данной работе.

6. **Точность детектирования без канала команды**: при использовании начала записи как опорного момента (quality=ESTIMATED) погрешность возрастает на величину задержки осциллографа относительно команды включения (обычно 20–100 мс в зависимости от настроек предзаписи).

### Сравнение с существующими подходами

Известны работы по диагностике выключателей по виброускорению [3], по времени движения контактов от специальных датчиков [4], по анализу токового импульса привода [5]. Предложенный подход отличается тем, что **не требует дополнительного оборудования** — используются каналы, уже записываемые штатным регистратором, и **не требует модификации прошивки терминала** — уставка обновляется через стандартный интерфейс IEC 61850 MMS, уже предусмотренный в ШЭ2607.

## 9. Заключение

Предложен метод автоматического определения и предсказания времени включения выключателя для функции улавливания синхронизма в АПВ. Метод основан на анализе осциллограмм в формате COMTRADE и не требует дополнительного оборудования или модификации терминала.

Ключевые результаты:
1. Алгоритм детектирования T_close на основе COMTRADE успешно работает на реальных данных с общей точностью ≥ 85%; двойной критерий залипания (t > 2000 мс ИЛИ t > 1.5 × медиана) охватывает все типы выключателей без ручной настройки
2. Фильтр Калмана с моделью дрейфа обеспечивает MAE ≈ 1.9 мс при walk-forward предсказании, что на порядок точнее ручного ввода из паспорта
3. Анализ тренда подтверждает реальность механической деградации на ~28% выключателей в датасете — обоснование необходимости непрерывной адаптации уставки
4. Автоматическое отклонение выбросов (залипания, аварии ТТ) через инновационный гейтинг обеспечивает надёжность в производственных условиях
5. Описана конкретная схема интеграции с терминалом ЭКРА ШЭ2607 016_200 через IEC 61850 MMS/GOOSE в АСУ ТП подстанции ФСК, включая механизм записи уставки и алгоритм диагностической сигнализации
6. Проанализированы варианты внутренней реализации: гибкая логика EKRASMS-SP Конфигуратора обеспечивает детектирование залипания и счётчик нештатных операций (разрешение ~10 мс), тогда как точное измерение T_close и Kalman-фильтр требуют либо SCADA-уровня (текущий вариант), либо нативного аппаратного модуля в прошивке терминала (перспективный вариант)
