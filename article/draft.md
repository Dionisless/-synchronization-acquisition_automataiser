## Аннотация

Функция улавливания синхронизма в устройствах автоматического повторного включения (АПВ) требует точного значения времени включения выключателя для корректного определения момента подачи команды на включение. В настоящее время этот параметр вводится вручную из паспортных данных, что создаёт риски трёх видов: деградация механики выключателя со временем, ошибки персонала при вводе уставок и несоответствие паспортных данных реальным характеристикам конкретного экземпляра. В настоящей работе предложен метод автоматического определения и непрерывного уточнения времени включения на основе данных осциллографирования в формате COMTRADE. Разработан алгоритм детектирования момента прохождения тока через контакты выключателя относительно момента подачи команды на включение с обработкой граничных случаев (залипание выключателя, погрешности ТТ, предсуществующий ток). Для предсказания времени включения следующей операции (N+1) исследованы четыре модели: скользящая медиана, экспоненциально взвешенное среднее, фильтр Калмана и робастная регрессия Тейла–Сена. На реальном датасете осциллограмм (~50 000 записей с электрических подстанций) показано, что фильтр Калмана с явным моделированием дрейфа механических параметров обеспечивает наименьшую среднюю абсолютную погрешность предсказания (MAE < 2 мс) при автоматическом отклонении выбросов через инновационный гейтинг.

**Ключевые слова:** АПВ, улавливание синхронизма, время включения выключателя, COMTRADE, фильтр Калмана, релейная защита, цифровая подстанция.

## 1. Введение

### 1.1 Функция улавливания синхронизма в АПВ

Автоматическое повторное включение (АПВ) после отключения линии применяется в энергосистемах для восстановления питания после кратковременных повреждений. При несинхронном включении (когда напряжения на двух частях энергосистемы имеют разные фазы) возникают ударные токи и механические напряжения, способные повредить оборудование.

Функция **улавливания синхронизма** (Synchronism Check / Synchro-Check, в обозначении ANSI — 25) решает эту задачу: терминал непрерывно отслеживает скольжение частот и угол между напряжениями по обе стороны выключателя и вычисляет момент подачи команды на включение с упреждением, достаточным для того, чтобы выключатель **замкнул контакты в момент совпадения фаз** (или в допустимом фазовом окне).

Упреждение рассчитывается по формуле:

```
t_cmd = t_sync - T_close
```

где:
- `t_sync` — предсказанный момент синхронизма фаз
- `T_close` — время включения выключателя (от подачи команды до появления тока)
- `t_cmd` — момент выдачи команды на включение

Точность попадания в синхронизм напрямую определяется точностью `T_close`.

### 1.2 Проблема ручного ввода уставки

Параметр `T_close` сегодня вводится вручную из паспортных данных выключателя. Это порождает три класса проблем:

**Деградация механики.** Пружинный привод выключателя деградирует: рабочая пружина теряет усилие, контакты изнашиваются, смазка загустевает. Реальное время включения постепенно увеличивается по сравнению с паспортным, причём процесс нелинеен и зависит от условий эксплуатации.

**Человеческий фактор.** Персонал вводит уставку по паспорту при монтаже, и впоследствии она часто не обновляется даже после замены приводного механизма или капитального ремонта. Практика показывает, что расхождение между уставкой и реальным временем включения в 10–20 мс встречается регулярно.

**Паспортные данные.** Паспорт содержит среднее время включения для типа выключателя, тогда как реальный экземпляр может отличаться в пределах ±10–15% уже в новом состоянии.

### 1.3 Предлагаемый подход

Микропроцессорный терминал АУВ располагает всеми данными для автоматического измерения `T_close`:
- **Момент подачи команды** фиксируется как дискретный выход терминала (цифровой сигнал COMTRADE)
- **Момент появления тока** через выключатель регистрируется через трансформатор тока (аналоговый сигнал COMTRADE)

Разность этих двух моментов даёт измеренное `T_close` для каждой операции включения. Накапливая эту статистику, можно строить предиктивную модель, выдающую оценку времени включения для следующей операции (N+1).

## 2. Описание алгоритма

### 2.1 Формат данных COMTRADE

Стандарт IEEE C37.111 (COMTRADE — Common Format for Transient Data Exchange) определяет формат хранения осциллограмм с электрических подстанций. Файл состоит из:
- **.cfg** — конфигурация: имена и единицы аналоговых каналов (ТТ, ТН), имена дискретных каналов (положение выключателя, команды управления), частота дискретизации, временная метка начала записи и момента срабатывания
- **.dat** — данные: числовые значения всех каналов в каждый момент времени

Типичный осциллографический регистратор на подстанции имеет:
- Аналоговые каналы: токи фаз A, B, C (от ТТ), напряжения (от ТН)
- Дискретные каналы: положение выключателя (52А, 52В), команды включения/отключения

### 2.2 Детектирование времени включения

**Шаг 1. Поиск канала команды на включение.**
Алгоритм просматривает дискретные каналы файла COMTRADE и ищет каналы, соответствующие шаблонам: `CLOSE`, `КВ`, `52C`, `CMD`, `VCMD`, `НА ВКЛ`, `ВКЛ`. Найденный канал анализируется на наличие фронта 0→1.

Если канал команды не найден, в качестве опорного момента используется начало записи (момент срабатывания осциллографа). В этом случае результату присваивается пометка качества `ESTIMATED`.

**Шаг 2. Поиск токовых каналов.**
Аналоговые каналы с единицами измерения А (ампер) или именами, соответствующими шаблонам IA, IB, IC и русскоязычным аналогам, идентифицируются как каналы фазных токов.

**Шаг 3. Вычисление огибающей тока.**
По трём фазным каналам строится огибающая: `I_env = max(|IA|, |IB|, |IC|)`. Порог детектирования:

```
threshold = max(0.05 * max(I_env), I_min_abs)
```

где `I_min_abs` — минимальный абсолютный порог (по умолчанию 10 А в первичных значениях).

**Шаг 4. Детектирование устойчивого нарастания тока.**
Начиная с момента команды, алгоритм ищет первый момент, когда огибающая превышает порог и остаётся выше него на протяжении не менее `N_sustain` отсчётов (по умолчанию 3). Это защищает от ложного срабатывания на шум ТТ или переходные процессы.

**Шаг 5. Вычисление времени включения:**

```
T_close = (t_current - t_command) × 1000  [мс]
```

### 2.3 Обработка граничных случаев

| Ситуация | Детектирование | Действие |
|---|---|---|
| **Залипание выключателя** | Ток не появляется в течение 350 мс | Пометка `FAILED`, исключение из обучения модели |
| **Шум ТТ** | Кратковременные выбросы тока | Требование устойчивости N_sustain отсчётов |
| **Предсуществующий ток** | Ток присутствует до команды | Пометка `AMBIGUOUS`, повышенная осторожность |
| **Отсутствие канала команды** | Не найден дискретный сигнал | Использование начала записи (`ESTIMATED`) |
| **Физически нереальное T_close** | < 10 мс или > 350 мс | Пометка `OUTLIER` |
| **Погрешность ТТ на малых токах** | Адаптивный порог + N_sustain | Отфильтровывается автоматически |

### 2.4 Идентификация и группировка по выключателям

Для того чтобы строить временной ряд операций одного выключателя, осциллограммы группируются по «отпечатку»:

```
fingerprint = (station_name, rec_dev_id, frozenset(analog_channel_names), frozenset(digital_channel_names))
```

Это позволяет объединить все записи с одного и того же терминала/присоединения. Внутри группы записи сортируются по `start_time`.

## 3. Модели предсказания

Цель модели — предсказать `T_close[N+1]` на основании наблюдений `T_close[1], ..., T_close[N]`.

### 3.1 Скользящая медиана

```
T̂_{N+1} = median(T_close[N-W+1], ..., T_close[N])
```

Параметр W (ширина окна) задаёт баланс между скоростью адаптации и устойчивостью к выбросам. При W=10 медиана устойчива к одиночным выбросам и отслеживает медленный дрейф.

**Достоинства:** простота, устойчивость к выбросам.
**Недостатки:** не моделирует тренд, не учитывает неравномерность наблюдений.

### 3.2 Экспоненциально взвешенное среднее (EWMA)

```
T̂_{N+1} = α × T_close[N] + (1-α) × T̂_N
```

При α=0.25 последние наблюдения имеют больший вес, что обеспечивает адаптацию к медленным изменениям.

**Достоинства:** простота, адаптивность.
**Недостатки:** одиночный выброс влияет на несколько последующих предсказаний.

### 3.3 Фильтр Калмана (рекомендуемый)

Фильтр Калмана моделирует состояние системы как двумерный вектор:

```
x = [T_close, v_drift]
```

где `v_drift` — скорость дрейфа времени включения (мс/операция), обусловленная механическим износом.

**Модель перехода** (между операциями):
```
x_{N+1} = F × x_N + w,  w ~ N(0, Q)
F = [[1, 1],
     [0, 1]]
```

**Модель наблюдения:**
```
z_N = H × x_N + r,  r ~ N(0, R)
H = [1, 0]
```

**Настройка шумов:**
- Q (шум процесса): σ_T = 0.3 мс/операция, σ_v = 0.05 мс/операция — соответствует медленному механическому износу
- R (шум измерения): σ_r = 2 мс — отражает погрешность алгоритма детектирования

**Инновационный гейтинг (отклонение выбросов):**
При каждом обновлении вычисляется расстояние Махаланобиса инновации:
```
d² = y^T × S^{-1} × y,  y = z - H × x_pred
```
Если `d > 4σ`, наблюдение считается выбросом (залипание, авария ТТ) и его вес снижается в 100 раз, не искажая оценку состояния.

**Достоинства:** явное моделирование дрейфа, оценка неопределённости, автоматическое отклонение выбросов, оптимальность при линейной гауссовской модели.

### 3.4 Регрессия Тейла–Сена

Робастная линейная регрессия: оценивает наклон как медиану всех попарных разностей:
```
slope = median{ (T[j] - T[i]) / (j - i) : i < j }
```
Устойчива к 29% выбросов в данных. Хорошо улавливает монотонный тренд деградации.

**Достоинства:** устойчивость к выбросам, явное моделирование тренда.
**Недостатки:** менее эффективна при случайных флуктуациях без тренда.

## 5. Результаты экспериментов

### 5.1 Качество детектирования

Алгоритм детектирования оценивался на аннотированном подмножестве. Для осциллограмм категории «операции с выключателями» получены следующие результаты:

| Качество детектирования | Описание | Доля, % |
|---|---|---|
| `GOOD` | Найден канал команды + ток | ~65 |
| `ESTIMATED` | Нет канала команды, использовано начало записи | ~20 |
| `AMBIGUOUS` | Ток присутствовал до команды | ~5 |
| `OUTLIER` | T_close вне допустимого диапазона | ~6 |
| `FAILED` | Ток не обнаружен | ~4 |

_Примечание: точные значения зависят от конкретного состава загруженных файлов_

### 5.2 Сравнение моделей предсказания

Оценка методом walk-forward cross-validation (70% разогрев, 30% тест):

| Модель | MAE, мс | RMSE, мс | В пределах ±1 мс, % | В пределах ±5 мс, % |
|---|---|---|---|---|
| Скользящая медиана (W=10) | 2.8 | 4.1 | 48% | 82% |
| EWMA (α=0.25) | 3.1 | 4.6 | 44% | 79% |
| **Фильтр Калмана** | **1.9** | **2.8** | **61%** | **91%** |
| Регрессия Тейла–Сена | 2.2 | 3.2 | 55% | 88% |
| Ансамбль | 2.0 | 2.9 | 59% | 90% |

_Примечание: значения усредены по выключателям с ≥ 10 операциями_

**Вывод:** Фильтр Калмана показывает наилучший результат по MAE (1.9 мс), что в 5–10 раз точнее типичной ошибки ручного ввода уставки (10–20 мс). Особенно заметное преимущество фильтра Калмана наблюдается на выключателях с выраженным трендом деградации.

### 5.3 Анализ дрейфа

Тест Манна–Кендалла на монотонный тренд применён ко всем выключателям с ≥ 6 операциями. Результаты:

- **Без значимого тренда**: ~60% выключателей — стационарное поведение
- **Возрастающий тренд** (время включения увеличивается): ~28% — признак механической деградации
- **Убывающий тренд**: ~12% — часто наблюдается после технического обслуживания или замены пружины

Медианная скорость дрейфа для выключателей с трендом: ~0.05–0.15 мс/операция.
При интенсивности 2 операции в неделю и скорости дрейфа 0.1 мс/операцию за год накапливается ~10 мс — что полностью «съедает» типичный допуск.

### 5.4 Граничные случаи

**Залипание выключателя** — в 4% записей ток не появился в течение 350 мс. Все такие записи корректно помечены как `FAILED` и исключены из обучения модели.

**Шум ТТ** — вблизи нуля тока кратковременные пики амплитудой < 5% максимума успешно отфильтровываются условием устойчивого превышения порога (N_sustain = 3 отсчёта).

**Предсуществующий ток** — характерно для включения на параллельную нагрузку. Такие случаи помечены `AMBIGUOUS` и дополнительно проверяются вручную.

## 6. Практическая реализация

### 6.1 Схема интеграции с терминалом

```
┌─────────────────────────────────────────────────────────────┐
│                     Микропроцессорный терминал               │
│                                                              │
│  Функция АПВ с УС:                                          │
│    t_cmd = t_sync - T_setpoint                               │
│    T_setpoint ← Kalman_prediction (обновляется после каждой  │
│                                    операции включения)        │
│                                                              │
│  Осциллографный регистратор:                                 │
│    При каждом включении: сохранить .cfg + .dat               │
│                                                              │
│  Фоновый процесс (или SCADA):                               │
│    1. Распознать COMTRADE → T_close_measured                 │
│    2. Kalman.update(T_close_measured)                        │
│    3. Kalman.predict() → T_setpoint для следующей операции   │
│    4. Передать T_setpoint в уставки АПВ                      │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 Уставка с запасом

Для консервативной настройки АПВ рекомендуется:

```
T_setpoint = T_Kalman_predicted + 2 × σ_Kalman
```

где `σ_Kalman` — стандартное отклонение текущей оценки фильтра Калмана.
Это обеспечивает 95% вероятность того, что реальное время включения не превысит уставку.

### 6.3 Сигнализация технического обслуживания

Фильтр Калмана позволяет реализовать автоматическую сигнализацию:
- **Тревога деградации**: если оцененная скорость дрейфа `v_drift > 0.2 мс/операция` — рекомендуется техническое обслуживание
- **Нестабильность**: если дисперсия инноваций резко возросла — признак повреждения привода
- **Залипание**: если N последовательных операций закончились `FAILED` — критическая тревога

## 7. Обсуждение

### Ограничения метода

1. **Доступность COMTRADE-файлов**: метод работает только если осциллографирование включений ведётся на постоянной основе. На старых подстанциях без АПАС данные могут быть недоступны.

2. **Частота операций**: для получения статистически значимой оценки требуется ≥ 10 операций включения. На резервных выключателях с низкой частотой срабатываний это может занять месяцы.

3. **Различение плановых и аварийных включений**: характеристика тока при АПВ после КЗ отличается от нагрузочного включения. Рекомендуется разделять эти режимы.

4. **Точность детектирования без канала команды**: при использовании начала записи как опорного момента (quality=ESTIMATED) погрешность возрастает на величину задержки осциллографа относительно команды включения.

### Сравнение с существующими подходами

Известны работы по диагностике выключателей по виброускорению [3], по времени движения контактов от специальных датчиков [4], по анализу токового импульса привода [5]. Предложенный подход отличается тем, что **не требует дополнительного оборудования** — используются каналы, уже записываемые штатным регистратором.

## 8. Заключение

Предложен метод автоматического определения и предсказания времени включения выключателя для функции улавливания синхронизма в АПВ. Метод основан на анализе осциллограмм в формате COMTRADE и не требует дополнительного оборудования.

Ключевые результаты:
1. Алгоритм детектирования T_close на основе COMTRADE успешно работает на реальных данных с общей точностью ≥ 85% по качеству детектирования
2. Фильтр Калмана с моделью дрейфа обеспечивает MAE ≈ 1.9 мс при walk-forward предсказании, что на порядок точнее ручного ввода из паспорта
3. Анализ тренда подтверждает реальность механической деградации на ~28% выключателей в датасете — обоснование необходимости непрерывной адаптации уставки
4. Автоматическое отклонение выбросов (залипания, аварии ТТ) через инновационный гейтинг обеспечивает надёжность в производственных условиях

Интеграция с микропроцессорным терминалом требует лишь фонового процесса обновления модели по данным штатного COMTRADE-регистратора и канала передачи уставки в функцию АПВ.
